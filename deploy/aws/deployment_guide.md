> **Deployment Status:** Configured for portfolio deployment. **Live AWS deployment is PENDING** your AWS account access and explicit approval of any cloud charges. No paid AWS resources have been provisioned.

## 1. Recommended Student Portfolio Architecture

A cost-conscious, security-first AWS architecture for this platform uses:

- **Amazon ECR (Private Repository):** Stores versioned Docker images built from `Dockerfile`.
- **Amazon EC2 (`t3.small`, Amazon Linux 2023):** Runs the FastAPI scoring container in a public subnet behind a restricted Security Group (or behind an Application Load Balancer with HTTPS/ACM in production).
- **PostgreSQL (Private):**
  - **Option A (Lowest Cost — Single EC2 with Private Docker Network):** Run PostgreSQL on the same EC2 instance via Docker Compose with port `5432` bound strictly to `127.0.0.1` / private Docker bridge (zero public DB exposure).
  - **Option B (Managed Database — Amazon RDS for PostgreSQL `db.t4g.micro`):** Place RDS in a **private subnet** with `Publicly accessible = No` and a Security Group allowing inbound TCP `5432` **only** from the EC2 instance's Security Group.
- **IAM Role for EC2:** Attach an IAM Instance Profile with `AmazonEC2ContainerRegistryReadOnly` and `CloudWatchAgentServerPolicy` (plus `AmazonSSMManagedInstanceCore` for keyless Session Manager access). **Never store static AWS access keys on EC2.**
- **AWS Systems Manager Parameter Store (or Secrets Manager):** Store `POSTGRES_PASSWORD` securely as a `SecureString` parameter rather than hardcoding secrets in scripts or Git.
- **Amazon CloudWatch Logs:** Configure the Docker `awslogs` driver to stream FastAPI container logs to a CloudWatch Log Group with a 14-day retention policy.

## 3. Prerequisites

1. An AWS account with IAM user/role permissions for ECR, EC2, VPC, and optionally RDS.
2. [AWS CLI v2](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) configured locally via `aws configure` (never commit `~/.aws/credentials`).
3. Docker Desktop running locally.
4. Trained model artifacts in `artifacts/models/` (generated by `python scripts/train_pipeline.py`).

## 4. Step 1 — Create ECR Repository & Push Container Image

```bash
export AWS_REGION="us-east-1"
export AWS_ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
export ECR_REPO="fraud-detection-platform"
export IMAGE_TAG="v1.0.0"

# Create private ECR repository with image scanning enabled
aws ecr create-repository \
  --repository-name "${ECR_REPO}" \
  --image-scanning-configuration scanOnPush=true \
  --region "${AWS_REGION}"

# Authenticate Docker to ECR
aws ecr get-login-password --region "${AWS_REGION}" | \
  docker login --username AWS --password-stdin "${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com"

# Build and push image
docker build -t "${ECR_REPO}:${IMAGE_TAG}" .
docker tag "${ECR_REPO}:${IMAGE_TAG}" "${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPO}:${IMAGE_TAG}"
docker push "${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPO}:${IMAGE_TAG}"
```

## 5. Step 2 — Network & Security Group Configuration

1. **EC2 Security Group (`fraud-api-sg`):**
   - Inbound TCP `8000` (or `443` via ALB/Nginx) from your IP or allowed CIDR.
   - Inbound TCP `22` ONLY from your personal IP (or omit entirely and use AWS SSM Session Manager).
   - **Never** open port `5432` to `0.0.0.0/0`.
2. **RDS Security Group (`fraud-db-sg`, if using Option B):**
   - Inbound TCP `5432` **ONLY** from `fraud-api-sg`.
   - Deploy RDS in a private subnet group with `Publicly accessible = No`.

## 6. Step 3 — Launch EC2 with `user_data.sh`

1. Create an IAM Role (`FraudApiEc2Role`) with `AmazonEC2ContainerRegistryReadOnly`, `AmazonSSMManagedInstanceCore`, and `CloudWatchAgentServerPolicy`.
2. Launch an Amazon Linux 2023 `t3.small` instance attaching `FraudApiEc2Role`, `fraud-api-sg`, and `deploy/aws/user_data.sh` as User Data.
3. Connect via SSM Session Manager or SSH, create `/opt/fraud-detection/.env` with your PostgreSQL credentials (never commit this file), copy your trained `artifacts/` directory (or pull from a private S3 bucket), and start the container:

```bash
# Authenticate EC2 to ECR using its IAM instance role
export AWS_REGION="us-east-1"
export AWS_ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
export ECR_URI="${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/fraud-detection-platform:v1.0.0"

aws ecr get-login-password --region "${AWS_REGION}" | \
  docker login --username AWS --password-stdin "${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com"

docker pull "${ECR_URI}"

docker run -d \
  --name fraud_detection_api \
  --restart unless-stopped \
  --env-file /opt/fraud-detection/.env \
  -v /opt/fraud-detection/artifacts:/app/artifacts:ro \
  -p 8000:8000 \
  "${ECR_URI}"
```

## 8. Step 5 — Cleanup (Avoid Ongoing Charges)

```bash
# 1. Terminate EC2 instance
aws ec2 terminate-instances --instance-ids <INSTANCE_ID> --region "${AWS_REGION}"

# 2. Delete RDS instance (if created)
aws rds delete-db-instance \
  --db-instance-identifier fraud-detection-db \
  --skip-final-snapshot \
  --region "${AWS_REGION}"

# 3. Delete ECR repository and images
aws ecr delete-repository \
  --repository-name fraud-detection-platform \
  --force \
  --region "${AWS_REGION}"
```
